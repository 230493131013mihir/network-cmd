Reading packets with Wireshark

22 min read Beginner Wireshark required

Installing Wireshark

Wireshark is free and runs on Windows, macOS, and Linux. Download it from wireshark.org. On Linux, install via your package manager:

BASH
# Debian / Ubuntu
sudo apt install wireshark

# Fedora / RHEL
sudo dnf install wireshark

# macOS (Homebrew)
brew install --cask wireshark
NOTE

On Linux, add yourself to the wireshark group so you can capture without sudo: sudo usermod -aG wireshark $USER, then log out and back in.

The Wireshark interface

Wireshark has three main panes:

  • Packet list — one row per packet, with timestamp, source/destination, protocol, and a summary
  • Packet details — the full decoded protocol tree for the selected packet
  • Packet bytes — the raw hex and ASCII of the packet

When you first open Wireshark, it shows you a list of available interfaces. Double-click an interface to start capturing on it.

Display filters

The filter bar at the top lets you narrow what you see without stopping the capture. These are display filters — they don't affect what gets captured, only what gets shown.

WIRESHARK DISPLAY FILTERS
# Show only HTTP traffic
http

# Show traffic to or from a specific IP
ip.addr == 192.168.1.50

# Show traffic between two hosts
ip.src == 192.168.1.10 && ip.dst == 192.168.1.20

# Show DNS queries only
dns.flags.response == 0

# Show TCP SYN packets (connection attempts)
tcp.flags.syn == 1 && tcp.flags.ack == 0

# Show packets on a specific port
tcp.port == 443

Following a TCP stream

One of Wireshark's most useful features is Follow TCP Stream. Right-click any packet and select it to see the full reconstructed conversation between two hosts — request and response together, in order.

This works for any cleartext protocol: HTTP, FTP, SMTP, Telnet. For encrypted traffic (HTTPS, SSH), you'll see ciphertext unless you have the session keys.

Capture filters vs display filters

There are two filter types, and mixing them up is a common mistake:

  • Capture filters — set before capture starts, use BPF syntax, reduce what gets written to disk. Useful on busy networks.
  • Display filters — applied after capture, use Wireshark's own syntax, don't affect stored data.
CAPTURE FILTER SYNTAX (BPF)
# Capture only traffic to/from port 80
port 80

# Capture only traffic from a specific host
host 192.168.1.100

# Capture everything except your own SSH session
not port 22

# Capture only TCP
tcp

Practical exercise: spot a port scan

A port scan sends SYN packets to many ports in rapid succession. In Wireshark, this shows up as a burst of TCP SYN packets from a single source to many destination ports, followed by RST or ICMP unreachable responses.

Filter to see it: tcp.flags.syn == 1 && tcp.flags.ack == 0. If you see hundreds of SYNs from one IP to sequential ports in under a second, that's a scan.

LEGAL NOTE

Only capture traffic on networks you own or have explicit permission to monitor. Capturing on a network without authorization is illegal in most jurisdictions.
