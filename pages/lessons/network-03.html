tcpdump on the command line

20 min read Beginner Linux / macOS terminal

Why tcpdump?

Wireshark is excellent when you have a GUI. On a headless server — which is where most interesting traffic lives — you need tcpdump. It's almost universally available, ships with most Linux and macOS systems, and is nearly identical in syntax to Wireshark's capture filters (both use BPF — Berkeley Packet Filter).

The workflow is typically: capture with tcpdump on a remote server, copy the .pcap file to your workstation, open in Wireshark for detailed analysis.

Basic syntax

BASH
# List available interfaces
sudo tcpdump -D

# Capture on eth0, print to screen
sudo tcpdump -i eth0

# Capture on eth0, save to file
sudo tcpdump -i eth0 -w capture.pcap

# Capture 100 packets then stop
sudo tcpdump -i eth0 -c 100

# Don't resolve hostnames (faster, avoids DNS leakage)
sudo tcpdump -i eth0 -n

# More verbose output (-v, -vv, -vvv)
sudo tcpdump -i eth0 -v

Filtering traffic

Filters go at the end of the command, after the options. They use BPF syntax:

BASH — COMMON FILTERS
# Only port 443 (HTTPS)
sudo tcpdump -i eth0 port 443

# Traffic to or from a specific host
sudo tcpdump -i eth0 host 10.0.0.5

# Traffic from a specific source
sudo tcpdump -i eth0 src 10.0.0.5

# Combine filters with 'and', 'or', 'not'
sudo tcpdump -i eth0 host 10.0.0.5 and port 80

# Everything except SSH (avoids capturing your own session)
sudo tcpdump -i eth0 not port 22

# Only TCP SYN packets (connection attempts)
sudo tcpdump -i eth0 'tcp[tcpflags] & tcp-syn != 0 and tcp[tcpflags] & tcp-ack == 0'

# Capture DNS queries only
sudo tcpdump -i eth0 port 53

Practical: capture and rotate files

On a busy interface you don't want one enormous PCAP file. Use -G (rotate every N seconds) and -W (keep only N files) to create a rolling capture:

BASH
# Rotate every 300 seconds, keep 12 files (1 hour of rolling capture)
sudo tcpdump -i eth0 \
  -w /var/captures/capture_%Y%m%d_%H%M%S.pcap \
  -G 300 \
  -W 12 \
  not port 22

Reading a saved PCAP file

BASH
# Read from file instead of live interface
sudo tcpdump -r capture.pcap

# Read and apply a display filter
sudo tcpdump -r capture.pcap port 80

# Print full packet contents in ASCII
sudo tcpdump -r capture.pcap -A

# Print in hex and ASCII
sudo tcpdump -r capture.pcap -XX
PRO TIP

Pipe tcpdump output through grep for quick searches: sudo tcpdump -i eth0 -A port 80 | grep "Host:" shows the HTTP Host header of every request, revealing which domains are being accessed.

Transferring captures to Wireshark

After capturing on a remote server, pull the file to your local machine with scp and open in Wireshark:

BASH
# Copy capture from remote server to your local machine
scp user@server:/var/captures/capture.pcap ~/Desktop/

# Then open in Wireshark from the command line
wireshark ~/Desktop/capture.pcap &
